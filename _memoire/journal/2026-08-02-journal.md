## 3. AI SEO du site de l'agence — les robots des IA étaient interdits d'entrée

**Le constat, mesuré :** `www.nebula-agency.online` répondait **403 à GPTBot, ClaudeBot et
PerplexityBot**, et servait un `robots.txt` « Cloudflare Managed » interdisant aussi
Google-Extended. Cause : **Cloudflare bloque les robots IA par défaut depuis le 1er juillet
2025**. Personne n'avait rien réglé.

**Le déblocage a demandé deux gestes, et le second est introuvable dans le tableau de bord :**

1. `is_robots_txt_managed` → désactivé par Mongazi. Notre `robots.txt` est enfin servi.
2. **`ai_bots_protection = block`** → passé à `disabled`. ⚠️ Ce réglage **n'est ni dans les
   règles WAF ni dans les réglages de zone** (comparés un à un entre un domaine bloqué et un
   domaine ouvert : rulesets identiques, 56 réglages identiques). Il vit dans
   `PUT /zones/{zone}/bot_management`, et le jeton doit porter **`Zone · Bot Management`**
   pour seulement le **lire**.

**Résultat : les 4 domaines répondent 200** à GPTBot, ClaudeBot, PerplexityBot,
OAI-SearchBot et Google-Extended.

## 4. Le bureau des partenaires ressuscité — Railway → Render + Supabase

**✅ LIVE : https://partenaires.nebula-agency.online** · cockpit `/cockpit-d59fa50d`

Railway avait fait **disparaître l'application** : l'origine elle-même répondait
`404 Application not found`, et le jeton du dépôt était refusé. Le VPS Hostinger envisagé
ensuite **n'appartient plus à Mongazi** : le certificat de `72.61.103.56` est au nom de
`api-preprod.normly.fr`, l'IP a été réattribuée. **Ne jamais y toucher.**

**Le montage :** code sur **Render** (gratuit, sans carte), données sur **Supabase**.
Ce n'est pas un luxe : **le disque de Render est éphémère**, un SQLite y serait effacé à
chaque redémarrage. Le domaine n'a pas bougé, seule l'origine du relais Cloudflare a changé.

**Le portage n'a réécrit aucune des 219 requêtes.** Couche `dbx.py` : `?`→`%s`,
`lastrowid`→`RETURNING id`, `sqlite3.Row`→dict, schéma `naff` posé par `search_path`.
Sans `DATABASE_URL`, on retombe sur SQLite : c'est le repli, et le moyen de tester.

Vérifié requête par requête avant d'écrire la couche : aucun `INSERT OR`, aucun
`executemany`, aucune fonction de date SQLite, `ON CONFLICT DO UPDATE` déjà en syntaxe
Postgres, un seul `%` et il est dans un paramètre.

⚠️ **`REAL` de PostgreSQL fait 4 octets et ARRONDIT un horodatage Unix.** Toutes les dates de
cette base en sont : elles sont donc en `double precision`.

⚠️ **`init_db()`/`migrate()` désactivées sur Postgres** : un `ALTER` qui échoue **empoisonne
toute la transaction**, donc le `try/except` d'origine ferait échouer tous les suivants.

### Trois pièges résolus

1. **L'auto-déploiement Render ne marche pas.** Le dépôt est branché par URL publique, sans
   l'application GitHub : GitHub ne prévient jamais Render, **un `git push` ne déploie rien**.
   Déclencher par `POST /v1/services/{id}/deploys`.
2. **Une requête sur huit repartait avec `x-render-routing: no-server`**, et ces requêtes
   **n'apparaissaient même pas dans les journaux** — l'indice décisif : elles n'atteignaient
   pas le code. L'hébergeur sondait `/`, qui dépend de la base, et une sonde `HEAD /`
   recevait **405**. → route **`/healthz`**, GET **et** HEAD, sans base ni disque.
   **Un point de contrôle ne doit jamais dépendre de la base.**
3. **Cloudflare renvoie 403 à un client d'API sans en-tête de navigateur** : un `urllib`
   Python nu ne peut pas se connecter au back-office.

### Le mécanisme : `scripts/rapatrier.py`

Le vrai problème n'est pas cette branche-là, c'est qu'**une session sur téléphone ou sur le
web pousse sur une branche `claude/…` qui n'arrive jamais dans `main` toute seule**.

Le script liste ce qui traîne, dit si la fusion passerait sans conflit, et **signale les
branches qui touchent du sensible** (contrat, socle, `server.py`, `_worker.js`, `secrets/`,
`CLAUDE.md`). Il ne pousse jamais seul.

⚠️ **Ne jamais fusionner en bloc.** L'état au 2026-08-02 le montre : la branche de mai
renommerait le site en `v7` (61 fichiers), une autre rajouterait une configuration Fly.io
abandonnée, et le PDF de commissions de juin décrit l'ancienne grille. Le script montre,
l'humain tranche.

Et une règle en tête de `CLAUDE.md`, lue par **toutes** les sessions, quelle que soit la
machine : récupérer `main` avant de fusionner vers lui, pousser, dispatcher la mémoire,
redéployer — et **le dire explicitement** quand la session ne peut pas pousser elle-même.
